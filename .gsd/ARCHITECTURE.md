## Overview

**aimhop-ERP** is an internal company Staff Management and Operations ERP built on Next.js App Router, TypeScript, Tailwind CSS, and Prisma ORM. It provides centralized workforce records, attendance logging, payroll/payments ledger, receipt snapshot generation, and audit logging with strict server-enforced Role-Based Access Control (RBAC) separating administrative actions from staff self-service.

## Data Flow

1. **Authentication Flow:** User enters credentials on `/login` -> POST to `/api/v1/auth/login` -> Verifies password hash via `bcryptjs` -> Issues HTTP-only signed session cookie -> Middleware directs user to `/admin/dashboard` or `/app/dashboard` based on role.
2. **Staff Read Request Flow:** Staff navigates to `/app/payments` -> Frontend calls `/api/v1/me/payments` -> API extracts session -> Applies `where: { staffId: session.staffId }` -> Returns only own records (IDOR immune).
3. **Admin Mutation Flow:** Admin creates/updates records (e.g., marks attendance or issues payment) -> Request validated with Zod -> Mutation saved via Prisma -> Audit log entry automatically created in `audit_logs` -> Receipt sequence incremented if payment receipt issued.

## Technical Debt

- [ ] **Database Provider Parity:** Local development uses SQLite (`prisma/schema.prisma`), while production specifies PostgreSQL in documentation and docker-compose. Moving between SQLite and Postgres will require schema provider updates and migration validation.
- [ ] **Automated Testing:** Currently no unit or end-to-end testing suite (e.g. Vitest/Playwright) is configured.
- [ ] **Document Upload Storage:** Document records are tracked in `StaffDocument`, but binary file upload integration (cloud S3/local multipart storage) is awaiting completion.
- [ ] **ESLint CLI Deprecation:** Next.js 15.5 warns that `next lint` is deprecated in favor of ESLint CLI for Next.js 16.

## Conventions

**Naming:**
- PascalCase for React components (`StaffEditForm.tsx`, `KpiCard.tsx`).
- kebab-case for routes, filenames, and component files (`attendance-mark.tsx`, `staff-form.tsx`).
- camelCase for TypeScript functions and Prisma field references.
- snake_case for mapped database column names in `schema.prisma`.

**Structure:**
- `src/app`: App Router pages and API routes (`/api/v1/*`).
- `src/components/ui`: Primitive design system components (`button`, `card`, `data-table`, `badge`).
- `src/components/admin`: Domain-specific administrative forms and modals.
- `src/components/staff`: Staff portal specific widgets.
- `src/lib`: Core utilities, database client, auth, rbac, and helpers.

**Testing:**
- Currently unconfigured; manual verification and seed data validation via `npm run db:seed`.
